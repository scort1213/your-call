# your-call · 一页纸判断库

> 让 AI 到了岔路口，先问自己一句："这事，你会怎么选？"

**English summary**: *your-call* turns the trade-offs you keep repeating to AI agents into a short, evidence-backed "one page" that Claude Code, Codex and other agents read at the start of every session — and lets you measure whether they actually decide more like you. Each judgment card cites your own words verbatim; nothing goes live until you confirm it.

---

## 它解决什么问题

你同时用好几个 AI Agent（Claude Code、Codex、Grok……），每开一个新项目，同样的话又得说一遍："一次只问我一个点""能用的版本先存起来再改""先跑个基线"。

各家自带的"记忆"有三个问题：

- **各存各的**：Codex 记住的，Claude 不知道；Claude 的记忆还是按项目文件夹隔开的。
- **没人确认**：都是 AI 自己决定记什么，记错了也照样生效。
- **没人检验**：存了以后，AI 的决定到底有没有更像你，没有任何数字。

your-call 的做法：**把你说过的话收割成"判断卡"，你点头才生效，压成一页纸发给所有 Agent，再用"猜中记录"量效果。**

```
你和 AI 的历史记录 ──收割──▶ 候选判断卡（每条附你的逐字原话）
                                │
                       核对原话（脚本逐字比对出处）
                                │
                   候选箱：你标"收 / 不收 / 改"（一次 5 条）
                                │
                   一页纸（只收确认过的通用卡，≤3000 字）
                                │
            发布到各家全局规则文件（先演示、你同意、先备份）
                                │
          猜中记录：AI 每次问你之前先猜，事后统计猜中率 ──▶ 回头修卡
```

## 功能

| 功能 | 说明 |
|---|---|
| **判断卡** | 一条取舍一张卡：**当**什么情况，**选**哪边，**而不是**另一边，**为什么**，适用 / 不适用，以及**你的逐字原话**作证据（日期 + 出处） |
| **原话逐字核对** | `核对原话.py` 检查每句原话都能在出处文件里找到；同时检查结构（必填字段、证据格式、编号唯一）。只出现一次的判断标"单例"，默认不进一页纸 |
| **候选箱** | 一次只给你看几条（默认 5 条），证据多的先给。在表格里写"收 / 不收 / 改"就行，写"收。"也认；写了看不懂的标注，整批不改并提示你 |
| **一页纸** | 只收你确认过的、适用于所有项目的卡；有字符上限（默认 3000）；关键节点放最前。超限、0 条时拒绝生成，旧文件不动 |
| **安全发布** | 只改目标文件里的一个标记块，块外内容不动；先演示 diff，`--apply` 才真写；写前备份；标记块残缺、一页纸是预览版或超限时，所有目标都不写 |
| **猜中记录** | 每次要问你之前，AI 先写下"我猜你会选 X"；事后补结果。`猜中统计.py` 按条件（基线 / 带一页纸）算出：猜中、叫多了（本可以自己定却来问）、走错（自己定却被你推翻）、漏问 |
| **回归测试** | `测试.py` 30 项，在临时目录里跑，不碰真实文件 |

## 快速开始

需要 Python 3.11+（只用标准库）。

```bash
git clone https://github.com/scort1213/your-call.git ~/.claude/skills/your-call
cd ~/.claude/skills/your-call/scripts
python3 测试.py
```

先用自带的示例库试一遍：

```bash
cd ~/.claude/skills/your-call/scripts
JUDGMENT_LIB=../examples/示例库 python3 核对原话.py
JUDGMENT_LIB=../examples/示例库 python3 候选箱.py
JUDGMENT_LIB=../examples/示例库 python3 一页纸.py --preview
```

正式使用：

1. 改 `配置.toml`，写上判断库放在哪（例如 Obsidian 库里的一个文件夹）、收割从哪些地方找材料、发布到哪些文件；
2. 在 Claude Code 里说"收割判断"，或输入 `/your-call`，按 `SKILL.md` 的步骤走；
3. 在 `候选箱.md` 里标注，然后说"候选箱标好了"；
4. 想发布时，先运行 `python3 发布.py` 看演示，确认后再 `python3 发布.py --apply`。

## 判断卡长什么样

```markdown
---
编号: J-02
标题: 能用的先存版本再改
类别: 取舍
范围: 通用
状态: 候选
一手证据: 2
分数: 0
---
# J-02 能用的先存版本再改

- **当**：一个版本已经能用、又想继续改时
- **选**：先存一个版本，在副本上改
- **而不是**：直接改唯一能用的那版
- **为什么**：保住能用的成果（概括，待确认）
```

## 几条设计原则

- **只写你说过的意思**：抽象时最容易出错的是添词、写宽、甚至写反。所以每条都要有逐字原话，而且要有 2 次独立出现才算数。
- **你点头才生效**：自动抽取不设闸门会变成垃圾场。有人审计过另一款记忆工具跑了 32 天的自动记忆，97.8% 是垃圾。
- **常驻只有一页**：规则越多，所有规则一起被执行得更差。所以一页纸设硬上限，领域专用的卡不进全局。
- **冲突不替你判**：两条判断打架时，标"可能冲突"，问你一次。
- **先量再信**：不在真实决策上量过猜中率，就不说"AI 更懂你了"。

背后的调研和来源见 [`docs/设计依据.md`](docs/设计依据.md)。

## 安全

- 判断库只在本地；发布只写你指定的规则文件，而且要先看演示、经你同意。
- 不碰任何登录凭证，只通过各家官方命令行运行。
- 判断库里不要放密码、令牌、账号信息。
- 你的判断卡含你的原话，**不要把自己的判断库提交到公开仓库**。本仓库只含工具和虚构的示例。

## 已知限制

- `核对原话.py` 只能证明原话存在，不能证明原话撑得住"选"。这一步要人看，或交给另一个模型做交叉评审。
- "收割"和"冲突判断"由 Agent 按 `SKILL.md` 来做，没有脚本。
- 猜中率要在真实任务里积累，样本少时只能看方向。
- `JUDGMENT_TARGETS` 用冒号分隔，所以路径里不能有冒号。
