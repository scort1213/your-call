# 设计依据

your-call 的每个设计选择背后，都有一条调研发现。下面只列打开原文核对过的来源，调研时间是 2026-10。

## 1. 市面上有没有现成方案

- 各家都有自己的记忆功能：Claude Code 的自动记忆、Codex 的 memories、Grok Build 的 memory。它们存的大多是**事实和具体做法**。我们没找到哪家专门存"取舍倾向"和"什么时候该问人"，也没找到有人测过"存了以后 AI 的决定是否更像用户"。
- 机制上最接近的开源项目是 [claude-reflect](https://github.com/BayramAnnakov/claude-reflect)：它把用户的纠正先放进队列，人审过才写进 `CLAUDE.md` 或 `AGENTS.md`，写入前还会查重。
- [Letta 的 Context Repositories](https://www.letta.com/blog/context-repositories)：记忆就是一个用 git 管理的文件夹，`system/` 里的文件每次完整读入，其余按需读；后台会定期整理。

→ your-call 沿用"常驻一小段 + 其余按需"的结构，补上三家都没有的三样：取舍倾向、用户确认的闸门、猜中率。

## 2. 为什么必须"你点头才生效"

- 有人在生产环境跑了 32 天的 mem0，逐条审计了 10,134 条自动记忆，只有 224 条留得下来，也就是 97.8% 是垃圾；同一句幻觉被复制了几百份（[mem0 issue #4573](https://github.com/mem0ai/mem0/issues/4573)）。

→ 候选卡默认不生效，只有标"收"的才进一页纸。

## 3. 为什么常驻只有一页

- ETH Zurich 的 [Evaluating AGENTS.md（arXiv 2602.11988）](https://arxiv.org/abs/2602.11988v1) 发现：
  - 规则文件让推理成本多出 20% 以上；
  - AI 自动生成的规则文件让任务成功率略降；
  - 人手写的提升也很有限。
  作者建议只写最低限度的要求。
- [Why Does CLAUDE.md Keep Growing?（arXiv 2608.11095）](https://arxiv.org/abs/2608.11095) 统计了 1,867 个仓库：规则文件在生命周期里平均涨 226%，越老的规则越没人删。**给每条规则写下理由**，能挡掉 99.3% 的多余规则。
- Anthropic 的 [Claude 5 一代上下文工程新规则](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)（2026-07-24）：删掉了 Claude Code 八成以上的系统提示，评测没有损失；`CLAUDE.md` 只写模型自己看不出来的东西。

→ 一页纸设硬上限，每张卡都必须写"为什么"，领域专用的卡不进全局。

## 4. 为什么要量"猜中率"，而且要分开看

- [HiL-Bench（arXiv 2604.09408）](https://arxiv.org/abs/2604.09408)：Agent 要自己判断什么时候该问人时，成绩大幅下降。瓶颈在"该不该问"，不在"会不会做"。
- [Ask Early, Ask Late, Ask Right（arXiv 2605.07937）](https://arxiv.org/abs/2605.07937)：
  - 目标类的澄清，过了执行的前 10% 就几乎没价值；
  - 拖过一半再问，比不问还差；
  - 现在的模型有 52% 的会话问得太多。

→ 猜中记录分开统计：**猜中**（选得对不对）、**叫多了**（本可以自己定却来问）、**走错**（自己定了却被推翻）、**漏问**（该问没问）。只看其中一个数，会鼓励 AI 什么都问，或者闷头乱走。

## 5. 安全

- Anthropic 的 [Claude Code 法律与合规文档](https://code.claude.com/docs/en/legal-and-compliance)：订阅登录只用于 Claude Code 等官方应用本身。

→ your-call 不碰任何登录凭证，所有自动化都通过各家官方命令行运行。
